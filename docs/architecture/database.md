# Database Architecture

## Engine

- PostgreSQL 16 (containerized via `docker-compose.yml`)
- Init SQL: `init.sql` mounted to `/docker-entrypoint-initdb.d/init.sql`

## Core Tables (Current)

- `accounts`
- `pending_payments`
- `contracts`
- `payables`
- `funds`

## Schema Characteristics

- Primary keys are integer IDs but are not auto-generated by sequences in current DDL.
- Most money fields are stored as integer cents (`BIGINT`), not decimals.
- Timestamp columns exist but are not defaulted/populated automatically in DB layer.
- Foreign key relationships are documented in comments but not enforced as DB constraints yet.

## Access / Permissions

- `init.sql` grants DB/table/sequence permissions to app user.
- API connects via `DATABASE_URL` from compose env wiring.

## ORM Relationship

- SQLAlchemy model currently exists only for `accounts` (`python/mp/schema/account.py`).
- If schema changes are made, update both:
  - SQL DDL in `init.sql`
  - Python ORM/Pydantic models in `python/mp/schema/`

## Operational Notes

- Data is persisted in named volume `postgres_data`.
- Recreating DB from scratch requires dropping volume (`docker compose down -v`).
